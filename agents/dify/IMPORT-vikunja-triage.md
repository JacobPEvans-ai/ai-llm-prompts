## Import and schedule

Target: Dify 1.16.1 or 1.18.0 with Workflow apps, Schedule Trigger support, and App DSL 0.7.0.

## Generated DSL source and synchronization

The workflow DSL is generated by `agents/dify-src/render.py` from `agents/vikunja-triage.yaml`, its workflow templates,
and the prompt sources declared by the YAML. Edit the YAML or canonical prompt source and run
`python3 agents/dify-src/render.py`; for graph changes, edit the template under `agents/dify-src/vikunja-triage/` too.
Commit all changed sources with the generated DSL. The CI check fails on any byte difference. Never copy or paste a
prompt by hand.

1. Configure the OpenAI-compatible provider and the `litellm_role` declared in `agents/vikunja-triage.yaml` (`medium`).
2. Configure the `vikunja` MCP provider and bind this app to its
   `agent-vikunja-triage` identity key through `openbao://agent-key/vikunja-triage`. Replace `VIKUNJA_MCP_PROVIDER_ID` in
   [vikunja-triage.dsl.yml](./vikunja-triage.dsl.yml) with its workspace identifier. Confirm the provider supports
   `list`, `update`, and `comment` operations.
3. Import [vikunja-triage.dsl.yml](./vikunja-triage.dsl.yml) as a **Workflow** app. Do not import it as a Chatflow. Set
   the native Schedule Trigger from `trigger.cron` in `agents/vikunja-triage.yaml` (`*/10 * * * *`, every ten minutes,
   minute resolution). Scheduled inputs are `{}`; the workflow uses `sys.timestamp`.
4. Publish with `VIKUNJA_TRIAGE_MODE=shadow`.

## Protected environment values

Resolve project policy refs to JSON arrays of opaque IDs. Keep all values in protected Dify settings; do not add real IDs or names here.

| Policy ref | Dify environment variable |
| --- | --- |
| `policy://vikunja-triage/allowed-projects` | `VIKUNJA_TRIAGE_ALLOWED_PROJECTS` |
| `policy://vikunja-triage/readonly-projects` | `VIKUNJA_TRIAGE_READONLY_PROJECTS` |
| `policy://vikunja-triage/rank-only-projects` | `VIKUNJA_TRIAGE_RANK_ONLY_PROJECTS` |
| `policy://vikunja-triage/denied-projects` | `VIKUNJA_TRIAGE_DENIED_PROJECTS` |

Also configure `VIKUNJA_TRIAGE_MODE` (`shadow` by default), `OPENBAO_ADDR`, `OPENBAO_ROLE_ID`, `OPENBAO_SECRET_ID`,
`GITHUB_READ_TOKEN_PATH`, `GITHUB_API_BASE`, and `GITHUB_WEB_HOST` using `<APPROVED_VALUE>` placeholders until
provisioned. The AppRole is `agent-vikunja-triage`; `GITHUB_READ_TOKEN_PATH` resolves `github-token/vikunja-triage` and
must mint a short-lived public-read token. Never log or return the token. Configure both GitHub bases to the approved
public service endpoints.

The guard refuses malformed policy, an unfiltered list, and every project absent from the policy. It lists only
`allowed ∪ readonly`, subtracting denied IDs; deny wins even when an ID appears on another list. `rank-only` must be a
subset of `allowed` and permits only priority/label updates. Readonly projects permit reads only.

## Enable Langfuse tracing

Do this before the first published run.

1. In the Dify console, open this app, select **Monitoring**, then **Tracing app performance**, then
   **configure**. Dify documents this at
   <https://docs.dify.ai/en/use-dify/monitor/integrations/integrate-langfuse>.
2. Enter the Public Key, Secret Key, and Host of the shared Langfuse project. Keep the values out of this
   file and out of Git. Read the two keys from the OpenBao KV v2 leaf named by the variable
   `DIFY_LANGFUSE_OPENBAO_PATH` in mount `secret`, fields `LANGFUSE_PUBLIC_KEY` and `LANGFUSE_SECRET_KEY`.
   Read the Host from the variable `DIFY_LANGFUSE_HOST`. Both variables come from the runtime secret store.
3. Save. The status on the same page must read started.
4. Acceptance check, after one test run of the published app: a Langfuse trace named `workflow_<workflow id>`
   exists, where `<workflow id>` is this app's Dify workflow id, recorded at import time. The router log has a
   line for that run, and its key is the one recorded at import for this app (the workspace key, or the agent
   key if a per-agent node is used). If the key differs, stop before any promotion.

## Shadow trace and promotion

Check the Langfuse trace for the scheduled Workflow run. Confirm its output contains the intended action JSON,
`mode: shadow`, and `dispatch: false`, and that no Vikunja write tool ran. Verify the trace uses the internal privacy
route and contains no credential values.

Promote `VIKUNJA_TRIAGE_MODE` to `live` only after the complete `agents/evals/vikunja-triage.yaml` set passes the judges
gate and the guard/policy configuration is verified. Live mode dispatches only guarded priority/label updates, verified
evidence comments, and completion updates whose GitHub reader result is merged or closed.
