## Import steps

Target: the Dify version deployed on the eval host, with App DSL 0.7.0. Confirm the running version at import, and record it
here before the first live run.

The app DSL is generated by agents/dify-src/render.py from agents/doc-contradiction-finder.yaml, the workflow template under
agents/dify-src/doc-contradiction-finder/, and the shared prefix and canonical prompt declared by the YAML. Edit those
sources, run python3 agents/dify-src/render.py, and commit the generated DSL with its source changes. Never edit a committed
DSL by hand.

1. Install the OpenAI-API-compatible model provider, configure its API Base URL and key in the Dify workspace, and add
   the medium chat model used by the agent.
2. Import doc-contradiction-finder.dsl.yml as a Workflow app.
3. Set these environment variables in the workflow environment:
   - OPENBAO_ADDR, the OpenBao base URL.
   - OPENBAO_ROLE_ID and OPENBAO_SECRET_ID, the AppRole values. Store both as secrets.
   - GITHUB_API_BASE, the GitHub API base URL.
   - GITHUB_TOKEN_MINT_PATH, the approved installation-token mint path. It must begin with a slash, because the workflow
     appends it to OPENBAO_ADDR.
   - GITHUB_TOKEN_READ_SET, the read-only token set referenced by github-token/doc-contradiction-finder. Do not configure
     a GitHub write set.
   - DOC_FINDER_PRIVATE_REPO, the private documentation repository name. Its value comes from the runtime secret store.
     The event router uses it to match the trigger; the workflow itself does not read it.
4. Have the event router start the workflow only for pull_request closed events with merged true in the dryvist org, on
   the base branch main. Pass the immutable repo and pr_number mandate and the event metadata. The workflow reads the
   changed .md pages of the pull request itself, at the merged commit, with the read-only token. It does not read the
   changed_pages, related_pages, or known_open_fingerprints start inputs, which stay declared until the router is
   updated. Related pages are empty in this version because only changed pages are read.
5. Keep the agent in shadow mode. The workflow returns only a JSON findings object for run-record storage. It has no
   Slack tool, no memory bank, and no documentation write operation. Dedupe: the validator compares each fingerprint,
   unchanged, with known_open_fingerprints, and a match sets ask to false. This version passes an empty list. The store
   reader that fills it is not bound yet and lives outside this repository. Posting and asking happen at a Slack step that is not bound in this
   repository, so the live channel stays disabled until that step is bound. The validator redacts each quote with the same rule
   it applies to the cited page before the verbatim check. A finding whose quote needed redaction carries security true and is
   never asked; the router sends it to the incident tracker, which is outside this repository.
6. Run two live checks on the published app before enabling the trigger:
   - a. Run on a merged pull request that changed a Markdown page. The run record must show changed_pages non-empty. This
     confirms that the build step reads the iteration output key correctly.
   - b. Run on a merged pull request with no Markdown changes. The run must return {"findings": []}. This confirms the
     empty-list path.

## Provider credential scope

1. The agent's router key is `agent-key/doc-contradiction-finder` from `agents/doc-contradiction-finder.yaml`.
   Dify sets model-provider credentials per workspace. This app uses the workspace key from step 1 unless the per-agent design question changes it.

## Enable Langfuse tracing

Do this before step 6, so the live checks produce traces.

1. In the Dify console, open this app, select **Monitoring**, then **Tracing app performance**, then
   **configure**. Dify documents this at
   <https://docs.dify.ai/en/use-dify/monitor/integrations/integrate-langfuse>.
2. Enter the Public Key, Secret Key, and Host of the shared Langfuse project. Keep the values out of this
   file and out of Git. Read the two keys from the OpenBao KV v2 leaf named by the variable
   `DIFY_LANGFUSE_OPENBAO_PATH` in mount `secret`, fields `LANGFUSE_PUBLIC_KEY` and `LANGFUSE_SECRET_KEY`.
   Read the Host from the variable `DIFY_LANGFUSE_HOST`. Both variables come from the runtime secret store.
3. Save. The status on the same page must read started.
4. Acceptance check, after the step 6a run: take the top-level `workflow_run_id` from the blocking response of that
   run's Workflow Run API call, documented at <https://docs.dify.ai/en/api-reference/workflow-runs/run-workflow>. A
   Langfuse trace with that id must exist.
   The router log line for this run's request shows the key alias that request used. Take the alias from that line.
   If the alias is not the one this app uses, stop before enabling the trigger.
